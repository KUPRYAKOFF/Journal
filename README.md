# Электронный журнал · пилот

Интерфейс для GitHub Pages и API Google Apps Script. Данные хранятся в закрытой Google-таблице. Все аккаунты из списка допуска могут смотреть журнал и вносить изменения.

В пилоте доступны оценки, посещаемость, комментарии к студентам и занятиям, вычитка, ведомость занятий, аналитика, CSV, расписание преподавателя и случайный выбор студента. Пустая отметка означает присутствие. При выборе конкретного занятия рулетка исключает отсутствовавших и студентов другой подгруппы.

## Запуск

1. **База.** Используйте подготовленную закрытую таблицу пилота. В ней четыре листа с точными именами `Groups`, `Students`, `Topics`, `Lessons`. Владелец развёртывания Apps Script должен иметь права редактора этой таблицы. В репозитории находятся только исходники. Значения отметок и примечаний лежат в `Lessons.marks` как JSON по идентификаторам студентов.
2. **GitHub Pages.** Из отдельного репозитория опубликуйте каталог `site/`. Можно перенести в корень отдельной ветки `gh-pages` только его содержимое, включая `.nojekyll`, и включить `Settings → Pages → Deploy from a branch → gh-pages / (root)`. Адрес сайта обычно имеет вид `https://<owner>.github.io/<repository>/`. Для OAuth важен завершающий слеш.
3. **Google OAuth.** В Google Cloud создайте проект и настройте Google Auth Platform. Для разных доменов выберите внешнюю аудиторию, для одного Google Workspace при необходимости используйте внутреннюю. Для внешнего приложения в режиме Testing добавьте разрешённые аккаунты в Test users. Создайте OAuth client типа **Web application** и добавьте полный адрес Pages в **Authorized redirect URIs**. Приложение запрашивает только `openid email`. Сохраните Client ID и Client secret.
4. **Apps Script.** Создайте отдельный проект, вставьте `server/Code.gs`. В настройках проекта включите отображение файла манифеста и скопируйте `server/appsscript.json`. В **Script properties** добавьте параметры ниже.
5. **Развёртывание API.** В Apps Script выберите **Deploy → New deployment → Web app**, выполнение от имени владельца, доступ **Anyone**. Доступность адреса нужна для входа с GitHub Pages. Проверка Google-аккаунта и списка допуска выполняется в коде перед каждым чтением или изменением. Скопируйте URL с окончанием `/exec`. Если организация запрещает режим Anyone, для этой схемы потребуется проект под аккаунтом, где такое развёртывание разрешено.
6. **Подключение сайта.** В опубликованном `config.js` укажите адрес `/exec` в `apiUrl`, OAuth Client ID в `googleClientId` и полный адрес Pages в `redirectUri`. URL должен в точности совпадать с URI из шага 3 и значением `OAUTH_REDIRECT_URI` на сервере.
7. **Приёмка.** В новой вкладке проверьте вход с разрешённым аккаунтом, чтение двух групп, запись и отмену тестовой правки. Повторите вход с Google-аккаунтом вне списка. Google в режиме Testing может отклонить вход раньше приложения. Чтобы проверить именно серверный отказ, тестовый аккаунт должен входить в список Google Test users и отсутствовать в `ALLOWED_GOOGLE_EMAILS`. Сверьте расписание и скачайте ведомость. Файлы сайта и таблицу храните отдельно.

| Script property | Значение |
| --- | --- |
| `DATABASE_ID` | Идентификатор закрытой Google-таблицы между `/d/` и `/edit` |
| `GOOGLE_CLIENT_ID` | OAuth Client ID типа Web application |
| `GOOGLE_CLIENT_SECRET` | OAuth Client secret, хранится в Apps Script |
| `OAUTH_REDIRECT_URI` | Точный URL опубликованного сайта |
| `ALLOWED_GOOGLE_EMAILS` | Разрешённые email через запятую |
| `SCHEDULE_TEACHER_ID` | Необязательный идентификатор преподавателя, по умолчанию 59 из исходного журнала |

Публичный адрес сайта показывает форму входа. Анонимные запросы к API получают отказ, а изъятие адреса из списка допуска прекращает доступ действующих сеансов. Изменение содержимого в редакторе журнала защищено проверкой версии на случай параллельной правки. Удалённая тема исчезает из вычитки и выбора для новых занятий. В уже проведённых занятиях её название сохраняется. Сеанс длится до одного часа и может завершиться раньше при очистке серверного кэша.

## Перенос и проверка

Подготовлены 2ТиТО-25 и 1ОП-26. Сохранены состав, подгруппы, отметки, даты, темы и примечания. Одна дата в вычитке 2ТиТО-25 осталась с отметкой `*`, поскольку в исходном журнале ей не соответствует занятие. Прежний лист «Доступы» и код студента в базе пилота отсутствуют.

Для повторной подготовки базы на копии исходника установите Python 3.10+ и openpyxl, затем выполните команду. Полученный файл содержит реальные данные и предназначен для закрытого импорта в Google Sheets.

```sh
python checks/migrate.py /путь/к/КГиД.xlsx /путь/к/Pilot.private.xlsx
```

Локальная проверка API использует тестовые данные и имитацию сервисов Google. Для запуска проверки интерфейса установите Playwright и Chromium. После настройки облака отдельно проверьте реальный OAuth-переход, междоменные запросы и запись в пилот.

```sh
node --test checks/api.test.cjs
node checks/browser.cjs
```

Для браузерной проверки укажите `CHROMIUM`, если исполняемый файл Chromium находится вне `/usr/bin/chromium`. В каталоге `preview/` показаны настольный и мобильный варианты интерфейса на вымышленных данных.
